# MIPT Hill Serpent

Собственный бот Battlesnake для домашнего задания 2. Работает в режимах Duels, Standard, Royale и Constrictor. Обучение нейросети и GPU не требуются.

Публичный API: https://mipt-hill-serpent.miniaturegoose4.chatgpt.site

## Локальный запуск

Требуется Node.js 22 или новее. Внешних npm-зависимостей нет.

```sh
npm start
```

Сервер слушает порт 8080. Другой порт: `PORT=9000 npm start`. Проверка: `curl http://localhost:8080/`. Поддерживаются `GET /`, `GET /health`, `POST /start`, `POST /move`, `POST /end`.

Контейнер с лимитом одного ядра:

```sh
docker build -t hill-serpent .
docker run --rm --cpus=1 -p 8080:8080 hill-serpent
```

Поиск синхронный, использует один поток JavaScript. У каждого хода есть ограничение по времени и числу узлов. Увеличение числа одновременных игр на одном процессе увеличивает время ожидания запросов.

## Алгоритм

Iterative deepening и maximin с alpha-beta отсечениями по совместным ходам всех живых змей. В Standard и Royale максимальная глубина 14 в дуэли и 6 при большем числе змей. Используется таблица транспозиций с точными значениями и границами для alpha-beta. В Constrictor сохранены глубины 10 и 4 и прежний порядок поиска. Локально бюджет 95 мс и 5000 узлов. На опубликованном Worker лимит снижен после сетевых измерений: 3000 узлов в дуэли, 1000 при нескольких змеях, в Constrictor 1000 для дуэли и 300 при нескольких змеях. Для воспроизведения облачного профиля локально: `SEARCH_PROFILE=cloud npm start`. Последняя полностью просчитанная глубина определяет ответ. Ограничение узлов действует и в средах с замороженными часами.

Модель учитывает одновременное движение, освобождение хвоста, дублированный хвост после роста, еду, голод, опасные клетки и столкновения голов по длине. Оценка позиции использует достижимое пространство, территорию по расстояниям, длину, еду, здоровье, мобильность и риск тесной ловушки. В Constrictor учитывается постоянный рост и оценка пути по цветам клеток и дереву двусвязных компонент. В Wrapped поддерживается переход через края.

Поиск использует уже известную еду и опасные клетки. Случайную будущую еду и направление следующего сжатия Royale он не предсказывает. Дальние освобождения тела оцениваются приближенно. Максимин для нескольких соперников предполагает их неблагоприятные для нас совместные действия.

## Проверка

```sh
npm test
npm run bench
python scripts/install-engine.py
```

В двух отдельных терминалах запустить `npm start` и `node scripts/opponents.mjs`, затем:

```sh
python scripts/evaluate.py
```

Используется официальный движок `BattlesnakeOfficial/rules v1.2.3`, таймаут 500 мс, 11 дуэлей против каждой из двух собственных тестовых политик и по 3 партии четырех змей в Standard, Royale, Constrictor. Порядок стартовых позиций меняется. `node scripts/verify-rules.mjs` сравнивает модель движения с сохраненными партиями официального движка. Журналы сохраняются в `results/games/`, сводка в `results/evaluation.json`. `greedy` и `oneply` — тестовые соперники, они не являются эталонами курса.

Для 11 игр против доступного HTTP API настоящего эталона:

```sh
python scripts/evaluate.py --opponent https://opponent.example --games 11 --output results/external.json
```

Локальный подбор коэффициентов методом hill climbing: `node scripts/tune.mjs`. Кандидат принимается только при строгом улучшении на фиксированных зеркальных стартах. Это короткая локальная настройка на упрощенном воспроизводимом симуляторе, а не подтверждение роста рейтинга. В проверенном запуске ни одна из шести мутаций не улучшила результат строго, исходные веса сохранены. Итоговые коэффициенты и протокол хранятся в `results/tuning.json`.

## Публикация

`worker/index.js` — тот же код для локального сервера и Cloudflare Worker. Хостинг Sites дает постоянный HTTPS-поддомен, работа не зависит от включенного ноутбука. Сборка: `npm run build && npm run validate`. Для повторной публикации через Sites использовать сохраненный `.openai/hosting.json`, не создавать новый проект.

Для любого другого хостинга достаточно запустить Dockerfile или `node server.mjs` и направить HTTPS-поддомен на порт из `PORT`. В арене нужно зарегистрировать API URL и добавить змейку во все четыре лидерборда. Состояние публикации, регистрации и фактические проверки описаны в `REPORT.md`.

Код стратегии написан для этого задания, исходники чужих змеек не использовались. Официальные правила: https://github.com/BattlesnakeOfficial/rules, контракт HTTP: https://docs.battlesnake.com/api/webhooks.

Команда финальной локальной серии из отчета:

```sh
python scripts/evaluate.py --seed-start 9001 --multi-games 5 --output results/evaluation-v12.json
```

Состояние настоящих игр можно читать без авторизации: `python scripts/arena-status.py GAME_ID`. Первые матчи и рейтинги перечислены в `REPORT.md` и `results/arena-games.json`.
